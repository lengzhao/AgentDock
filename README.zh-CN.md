# AgentDock

**让你常用的 Agent 成为随时可用的常驻助手。**

[English](README.md) | 简体中文

AgentDock 希望让已有 Agent 更容易接入消息平台：选择 Agent，通过引导连接平台，然后让它在本机后台持续运行。

你可以继续使用熟悉的 Claude Code、Codex、Pi、Grok、Kimi 等 Agent，由 AgentDock 负责平台连接、本地服务管理和凭据存储。

> **当前状态：早期开发。** 第一个代码里程碑已完成：可用的 `agentdock` CLI（配置引导、前台与 launchd 后台运行、分层诊断、ACP 适配器目录、所有者绑定、任务运行记录）。尚未提供发布安装包，也尚未在真实 Lark 租户上完成经过验证的端到端联调。已实现与规划中的能力分界见 `docs/development.md`。

## 为什么做 AgentDock？

把 Agent 接入消息平台，往往需要自己安装 CLI、获取平台凭据、编辑配置并管理后台进程。AgentDock 希望把这些操作收敛为一次配置引导。

- **直接使用已有 Agent**：复用它们的执行能力和受支持的登录流程。
- **连接消息平台**：引导配置平台权限、验证凭据，并通过测试消息确认连接。
- **后台持续运行**：管理本地后台服务，提供启动、停止、重启和状态查看。
- **使用系统凭据库**：API Key、App Secret、Token 等敏感值不写入普通配置文件。
- **提供可操作的诊断**：发现缺失依赖、凭据过期和连接失败，并给出修复步骤。

## 目标使用流程

1. 安装 AgentDock。
2. 选择 Agent，检测安装状态，并完成必要的登录。
3. 选择消息平台，通过引导完成授权或应用配置。
4. 安全保存凭据，验证平台连接。
5. 启用后台服务，发送测试消息。

目标是让用户无需手工拼装运行配置，就能获得一个可用的助手。必要的平台权限、管理员审批和 Agent 登录仍会在引导中明确呈现。

## 架构与职责

```text
消息平台
   │
   ▼
AgentDock
  配置引导 · 凭据管理 · 服务生命周期 · 状态诊断
   │
   ▼
AgentKit
  平台集成 · 会话 · 路由 · Agent 适配
   │
   ▼
已有 Agent
  Claude Code · Codex · Pi · Grok · Kimi · …
```

AgentDock 是基于 [AgentKit](https://github.com/lengzhao/agentkit) 的独立产品。AgentKit 提供可复用的运行能力，AgentDock 负责安装和日常使用体验。AgentDock 不依赖 agent-harness。

Agent 适配优先采用受支持的 ACP 接口，其他接入机制按 Agent 分别评估。流式输出、权限确认、取消和会话恢复能力取决于具体适配器，后续将明确记录。上面列出的 Agent 是接入目标，不代表已经兼容。

## 平台接入引导

平台引导应尽量自动完成官方支持的操作：

- 平台提供授权流程或应用创建 API 时，优先使用官方能力。
- 必须人工创建应用、配置权限或等待审批时，提供清晰的操作引导。
- 通过受支持的流程获取凭据，安全保存并验证访问能力。
- 连接验证通过后，才报告配置完成。

自动获取凭据是平台能力允许时的目标，不意味着所有平台都能通过 API 创建应用或读取 Secret。

## 凭据与后台服务

计划使用 [`zalando/go-keyring`](https://github.com/zalando/go-keyring) 访问操作系统凭据库。普通配置仅保存凭据引用，日志和诊断输出必须对敏感值脱敏。

已有 Agent 尽量继续管理自身的登录状态。AgentDock 复用其支持的登录流程，避免另行复制和保管 Agent 的认证信息。

后台运行需要在实际服务身份下验证，包括可执行文件查找和凭据读取。用户登录要求、凭据库锁定、无桌面 Linux 环境都需要明确处理；仅对已验证的配置声明支持无人值守。凭据库不可用或已锁定时，应给出可操作的错误提示，不静默降级为明文存储。
