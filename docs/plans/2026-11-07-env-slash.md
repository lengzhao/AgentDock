# Unified /env implementation plan

**Goal:** Owner-only private slash commands manage per-agent environment values in Keychain, with references in config and resolved values injected into ACP child processes after restart.

**Architecture:** Add an env command provider using the existing access store and credential store. All set values use new scoped Keychain accounts; verify readback before atomic config save. List names only; check readability without revealing values; unset removes the reference while retaining credential rollback data. Resolve references only in runtime memory and preserve literal nonsecret legacy env settings. Explicit configured env overrides inherited shell env.

**Tech Stack:** Go, AgentKit CommandProvider, go-keyring, existing YAML config.

## Steps
1. Write failing tests for secret-reference config validation and runtime resolution, including unavailable references and no mutation of original config.
2. Implement in-memory env resolution at Build before graph assembly, without serializing resolved values or leaking backend errors.
3. Write failing slash tests for owner/private authorization, set/list/check/unset, opaque values, config preservation, failures, argument log redaction, and different Agent isolation.
4. Implement provider wiring, config-file update locking, fresh-account writes plus readback verification, atomic save, safe errors and restart-required replies.
5. Run focused/full/race tests and review. Update documentation, rebuild, reinstall existing LaunchAgent, verify registration and real Keychain reference injection using a nonsecret value.

Sensitive values typed into Lark remain in the platform message history; Keychain storage does not remove the original chat message. Never include values in command replies or diagnostic logs.
