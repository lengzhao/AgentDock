# 公开模块与插件装配设计

用户已确认：取消 internal；模块通过接口可替换，集中装配默认实现。

所有原 internal 包迁至顶层，保留单一 Go module，cmd 仅启动 CLI。凭据 Store、服务 ServiceManager、目录 Source 由插件工厂构造，CLI 只依赖契约。通过命令参数选择已注册插件，默认配置兼容现有安装。运行图支持按实例 ID 完整替换节点，以复用 PluginKit 的依赖验证和生命周期；替换者负责满足消费者接口及配置契约。准入链默认保持所有者校验、去重与验证顺序，只有显式替换才改变。

不采用动态 Go 二进制加载；外部扩展在自定义入口导入插件注册后重新编译。纯数据和工具包无需为形式而增加插件接口。当前 Lark setup/owner 流程仍是平台专属能力，新增平台须提供对应引导适配，不能仅更改运行图便声称完成全产品支持。

验证：现有测试全量回归；插件替换测试覆盖自定义凭据、错误类型、未知 kind；运行图替换覆盖自定义节点及默认图不受影响。
